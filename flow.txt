strategy
signal_engine
    check(symbol, df_1h, df_15m)
    │
    ├─ Step 1. 지표 계산
    │   ├─ ti.calculate(df_1h)   → TrendResult
    │   ├─ mi.calculate(df_15m)  → MomentumResult
    │   └─ vi.calculate(df_15m)  → VolumeResult
    │
    ├─ Step 2. 방향 판단 (AND 필터)
    │   ├─ _check_long()   → (True/False, 거절사유)
    │   └─ _check_short()  → (True/False, 거절사유)
    │        둘 다 False → 즉시 HOLD 반환
    │
    ├─ Step 3. 보조 점수 계산 (OR 가산)
    │   ├─ _score_long()   → (score, {조건명: 점수})
    │   └─ _score_short()  → (score, {조건명: 점수})
    │
    ├─ Step 4. 최소 점수 필터 (score < 5 → HOLD)
    │
    └─ Step 5. 신호 확정 → SignalResult 반환

signal_scorer
    evaluate(SignalResult)
    │
    ├─ [Step 0] BTC 시장 필터  (signal_engine._check_btc_market)
    │           알트코인에만 적용, BTC 자신은 스킵
    │   ├─ BTC ATR > 3%              → HOLD  (급변동 구간)
    │   └─ BTC EMA20<EMA50 + -DI우세 + ADX>=30 → HOLD  (하락 추세 강화)
    │
    ├─ base_score      signal_engine 보조 조건 점수 (0~22)
    │
    ├─ _calc_context() 멀티 타임프레임 일치도 보너스 (0~30)
    │
    │   ── 1단계: 선행 거래량 / CVD — 에너지 방향 확인 (최대 12점) ──
    │   ├─ CVD매수 + OBV상승 동시                +5  ← 스마트머니 매집 포착
    │   ├─ 방향성 양봉/음봉 + 3x급등             +4  ← 패닉 투매 필터 (ATR>4% 제외)
    │   └─ 다이버전스 + 거래량급등 동시          +3  ← 반전 초기 포착
    │
    │   ── 2단계: 모멘텀 조합 — 진입 타이밍 확정 (최대 10점) ──
    │   ├─ MACD크로스 + StochRSI크로스 동시      +5  ← 두 모멘텀 동시 전환
    │   ├─ BB Squeeze 탈출 + ATR급증             +3  ← 에너지 응축→폭발 구간
    │   └─ RSI방향 + MACD 모멘텀 강화 동시       +2  ← 추세 지속 확인
    │
    │   ── 3단계: 후행 추세 부스트 — 방향 신뢰도 강화 (최대 8점) ──
    │   ├─ EMA 완전배열 + 강한추세 동시          +4  ← 타임프레임 동기화
    │   ├─ ADX >= 50 초강세                      +2
    │   └─ 골든/데드크로스 + EMA배열 동시        +2
    │
    ├─ _calc_penalty() 위험 요소 감점 (-28~0)
    │   ├─ 역방향 다이버전스                     -6  ← 가장 강한 위험 신호
    │   ├─ BB 불리한 경계 근접                   -5
    │   ├─ RSI 극단 구간 진입                    -5
    │   ├─ OBV 방향 반대                         -4
    │   ├─ StochRSI 극단 구간                    -4
    │   ├─ ADX 경계선 불안정 (25~28)             -2  ← -4에서 완화 (이중 처벌 방지)
    │   ├─ EMA200 역행 진입                      -3
    │   ├─ 거래량 배수 낮음 (1.0~1.5x)          -3
    │   └─ BB 과열 돌파 진입                     -2
    │
    └─ confidence = (base + context + penalty) / 52 × 100
         RAW_MAX = base_max(22) + context_max(30) = 52

circuit_breaker
    record_trade(pnl) 호출
    │
    ├─ pnl ≥ 0 → 수익
    │   └─ consec_losses 리셋
    │
    └─ pnl < 0 → 손실
        ├─ daily_loss += |pnl|
        ├─ consec_losses += 1
        └─ _evaluate_halt_conditions()
            ├─ daily_loss ≥ 자본×3%  → DAILY_HALT  (자정까지)
            └─ consec_losses ≥ 3     → COOLDOWN    (1시간)

    자정 백그라운드 스레드
        └─ _do_daily_reset()
            ├─ 통계 초기화
            └─ DAILY_HALT 자동 해제

    쿨다운 만료 체크 (check() 호출마다)
        └─ time.time() ≥ cooldown_until → CLEAR

leverage_manager
    decide(symbol, score, cb_status)
    │
    ├─ Step 1. base_leverage   ← signal_scorer.leverage
    │
    ├─ Step 2. _calc_market_mult()   ADX + ATR 보정 (0.5 ~ 1.2)
    │   ├─ ADX ≥ 40  강한추세     → +0.2
    │   ├─ ADX < 28  불안정       → -0.2
    │   ├─ ADX < 25  횡보         → -0.5
    │   ├─ ATR% > 4% 고변동성     → -0.3
    │   └─ ATR% < 1.5% 저변동성   → +0.1
    │
    ├─ Step 3. _calc_risk_mult()     손실률 + 연속손절 보정 (0.5 ~ 1.0)
    │   ├─ 일손실 ≥ 2.5%            → ×0.6
    │   ├─ 일손실 ≥ 1.5%            → ×0.8
    │   ├─ 연속손절 ≥ 2회           → ×0.7
    │   └─ 연속손절 ≥ 1회           → ×0.9
    │
    ├─ Step 4. adjusted = base × market × risk (소수점 버림)
    ├─ Step 5. clamp(adjusted, MIN=1, symbol_max)
    └─ Step 6. _set_exchange_leverage()  거래소 API 호출 (캐시 확인 후)

 signal_scorer
    [v1 → v2] signal_scorer 재설계
    - 판단 순서 역전: 추세(후행) → 거래량(선행) → 모멘텀 → 추세(확인)
    - BB Squeeze 탈출 + ATR 급증 신규 추가 (+3)
    - 투매 필터: ATR > 4% 시 거래량 급등 보너스 제외
    - 후행 추세 비중 축소: 13점 → 8점
    
    [v2 → v3] BTC 시장 필터 추가
    - Step 0 신설: BTC 급변동·하락추세 시 알트 진입 HOLD 게이트
    - 거래량 지속성 보너스 +1 추가 (일시적)
    
    [v3 → v4] 중복 필터 제거 및 감점 완화
    - MACD 모멘텀 약화 (-3) 제거
        └─ 이유: 필수 조건(MACD hist > 0) + 보너스 미달로 이미 처리됨 → 이중 처벌
    - 거래량 지속성 보너스 (+1) 제거
        └─ 이유: CVD+OBV 동시 방향(+5)에 지속성 개념이 이미 포함
    - ADX 경계선 불안정 -4 → -2 완화
        └─ 이유: 필수 조건(ADX≥25) 통과 후 추가 -4는 이중 처벌, -2가 적절
